# 生成前試映：16 宮格分鏡草圖＋文字讀本

> 目的：在首幀與 H3 之前，先讓使用者**看到故事、跟著字幕讀一遍節奏**，抓出「節奏太快」「轉折沒交代」「片長超標」。
> **2026-10-23 起讀本只給文字、不先做 TTS**：台詞之後由 H3 拿角色參考音自己念（`docs/02` §6），讀本聲音用不到成片裡；片長與每鏡 H3 長度改用字數估。要先「聽」一遍才做 TTS 讀本（第 5 節）。
> 試映素材只給使用者內部看，不上片。檔案放 `<片資料夾>/preview/`：`shots.json`、`storyboard_<k>.png`、`storyboard_<k>_label.png`、`讀本_timeline.json`、`讀本試映.mp4`。
> 原頻道實測：一支 27 鏡的 Shorts，草圖約 3 分鐘、組成試映影片 1 分鐘；使用者看完把 99.7 秒刪到 88.6 秒才進首幀。

## 0. 先把鏡表寫成 `preview/shots.json`

兩支工具共用同一份檔案（欄位說明也在兩支工具的開頭）：

```json
{
  "cast": "Characters (keep consistent across panels): TEACHER = ...; KID = ...",
  "shots": [
    {"id": "S01", "sec": 3, "panel": "extreme close-up: a boy thrusts a phone at the camera",
     "lines": [{"text": "老師！颱風轉過來了！", "caption": "阿福：老師！颱風轉過來了！"}]},
    {"id": "S02", "sec": 2.5, "panel": "the whole class jumps up cheering",
     "lines": [{"caption": "（全班歡呼）喔——！"}]}
  ],
  "end_card": "你的頻道名"
}
```

- `panel`：給草圖用的一句英文畫面描述（誰、在哪、做什麼、景別）。
- `lines`：`text`＝角色要念的字（不含說話者，之後 H3 spec 的台詞一字不差照抄）；`caption`＝試映畫面的字幕。群眾聲、音效、字卡說明只寫 `caption`。
- `sec`：鏡表秒數。

## 1. 16 宮格分鏡草圖（`tools/make_storyboard.py`）

```
python tools/make_storyboard.py <片資料夾>/preview/shots.json
```

- 每 16 鏡一張 4×4（27 鏡就是 2 張），多張同時生成。用 `tools/img25.py`（OpenAI Image 2.5，要 `OPENAI_API_KEY`）。沒有金鑰就跳過草圖，第 2 步的試映影片會只有字幕（片長估法不變）。
- 提示詞是「鉛筆草圖＋淡水彩、每格一鏡」，**不叫模型在格子裡寫字**（會寫錯）；畫好後用 PIL 在每格左上角疊鏡號。
- **不附角色參考圖**——只看故事順序與構圖，不驗角色像不像。交給使用者時要說明「這是看節奏用的草圖，不是首幀」。

## 2. 組成文字讀本試映（`tools/assemble_read.py`）

```
python tools/assemble_read.py <片資料夾>/preview/shots.json
```

- 照鏡表排時間軸 → `讀本試映.mp4`（720×1280，草圖一格一格切換、下方是字幕；**靜音**，每句照一般語速每秒 4 字停留）＋`讀本_timeline.json`（每鏡起訖秒數、台詞字數 `chars`、建議 H3 鏡長 `h3_sec`）。
- **H3 鏡長用 `h3_sec`**＝max(3 秒, 鏡表秒數, 台詞字數 ÷ 3＋2 秒)，取到 0.5 秒；字數＝中文字＋英數字，不含標點。
  - 依據（原頻道〈颱風假作業包〉）：H3 用參考音自己念，每秒約 2.3–4.7 字，而且 14 句裡有 5 句晚 1.5–2.1 秒才開口；用這個公式，開口時間可靠的 7 句全部在鏡頭內念完（最緊的 13 字句算出 6.3 秒、實際念到 6.16 秒）。
  - 估長一點沒關係：剪接時照 H3 實際開口時間裁掉空白，只是多花一點生成時間。`h3_sec` 超過 12 秒的鏡要拆。
- 回報：**估計總長 vs 目標**、最長的三鏡、超出鏡表秒數的鏡、要拆的鏡。

## 3. 給使用者的試映包

- 試映影片＋草圖＋一張表（鏡號／估計秒數／台詞），標出你自己覺得可能太快、沒講白的地方，請使用者看的時候特別注意。
- 說明：這是文字讀本，沒有聲音；語氣、停頓等成片出來再看，念錯的句子那時再修。
- 超長就**刪台詞或併鏡**，不要加速。使用者說「通過」才進首幀。

## 4. 之後的聲音流程（H3 階段）

- 每個角色一份參考音（你有權使用的真人錄音，10–20 秒、乾淨、平常講話語氣），定了就不換。角色要吼、喊口令的戲，**另錄一份兇的參考音**（平常語氣的參考音念兇的口令會偏溫和）。
- H3 spec 寫 `audio.voice_ref`；兩三人對話同鏡就寫 `audio.voice_refs`（各給參考音，最多 3 位）；鏡長用 `h3_sec`。
- 跑完聽寫比對原文 → 念錯／改用詞的換 seed 再抽 2 次 → 還是錯：**請配音的人錄那一句**，當固定音軌（`audio.fixed`）給 H3 對嘴、只重跑那一鏡；只錯一兩個字先用 `tools/vc_swap.py` 換字；沒人能錄才用 Ming-3.0-TTS 固定音軌（`tools/make_ming.cmd`，這時才需要第 5 節的讀音修法；BreezyVoice 為再備案）。
- 寫劇本時就避開 H3 容易改掉的說法（例：「二十四號」會被念成「二十四日」）。

## 5. （選用）TTS 讀本：使用者要先「聽」一遍時才做

- 每句台詞一個 job，用該角色**定稿參考音**（`ref_audio`＋`ref_text`），每句 2–4 個 seed 就好：`tools/make_ming.cmd jobs.json`（Ming-3.0-TTS，格式見 `tools/make_ming.py` 開頭；BreezyVoice `tools/make_breezyvoice.cmd` 也可）。有裝 Breeze TTS 2 也可用 `tools/breeze_batch.py`（**產出不可營利**，讀本只內部聽沒關係）。
- 把挑中的音檔寫進 shots.json 的 `"wav"`（相對 shots.json），再跑同一支 `assemble_read.py`：有 `wav` 的句子照實際音長排、試映影片有聲音。
- **念錯的字要修**（讀本是使用者第一次聽到台詞，念錯會被當成劇本問題）：
  - 例：Breeze 會把「颱風」的「颱」念成四聲（像「泰」）→ 配音輸入寫「**抬**風」（字幕照原字）。「防災」被念成「放發」→ 輸入「防**栽**」。
  - 聽寫（ASR）只驗字、不驗聲調：關鍵字要量音高曲線（`tools/pron_check.py`），二聲要「從低處上揚」，判 unsure 就當不合格。
  - 修過的讀音記進你自己的讀音修正表，下一支片先查。
- 配音工具若用名稱快取（同名候選會跳過），換了輸入文字要**換 job 名稱**，不然拿到的還是舊音檔。
