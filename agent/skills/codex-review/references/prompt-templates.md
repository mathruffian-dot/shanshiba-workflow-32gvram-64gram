# 提問檔範本

每個範本都是 `--ask` 那個檔的內容。`〔〕` 裡換成實際內容。附件用 `--attach`、圖用 `--image`，不要貼進提問檔。
限字數照實際需要調：第一輪 800–1,500 字，複審 200–700 字。

## 1. 計畫、專案結構（第一輪）

```
你是這個專案的外部審核者。請用繁體中文，獨立審核後面附的「〔提案名稱〕」，不要只是確認它。

背景：〔一兩句：這是什麼專案、誰在用、使用者的要求原文〕。你無法讀本機檔案，判斷依據是附件：提案（含盤點事實）與專案的 CLAUDE.md 全文。

請回答：
1. 逐項給判定：採用／修改後採用／不要做，各一兩句理由。特別指出會弄壞現有流程、遺失規則、或害到正在工作的其他工作階段的風險。
2. 優先順序對不對？哪一項的效益被高估或低估？
3. 提案漏掉了什麼更值得做的？
4. 〔這次最沒把握的一點〕怎麼做才能保證〔不出事的條件〕？請給具體驗證方法。
5. 最後給你建議的執行順序（最多 8 步）。

直接講結論，不要客套，總長 1,500 字以內。
```

## 2. 程式、共用工具

```
請用繁體中文審後面附的程式與驗證結果，〔700〕字以內，直接講結論：
1. 程式有沒有 bug、放行邏輯有沒有洞（哪種情況會回傳「通過」卻不該通過）？列最嚴重的，附改法。
2. 驗證夠不夠？還缺哪個案例？
3. 這一版可不可以開始用？

這支工具的用途：〔做什麼、吃什麼輸入、誰會呼叫它、實際的輸入長什麼樣〕。
我實際跑過的測試與結果：〔逐項列，數字照實寫；沒跑的寫沒跑〕。
```

## 3. 複審（第二輪起，加 `--with-prev`）

```
第〔N〕輪。你上一輪的意見附在最前面，下面是我照做的結果。請用繁體中文、〔300〕字以內，第一行寫「〔可以開工／可以推送〕」或「先不要」。
請分兩類：(A) 擋的——〔照這次審的東西寫，四選一或自己寫：
　・劇本、成片：劇情邏輯對不上、第一次看的觀眾看不懂、畫面連戲錯誤、使用者叫修過的同類問題再犯
　・程式、工具：在實際用途（寫明用途）下會把有問題的東西報成通過、會弄壞資料
　・公開推送：會洩漏不該公開的內容、程式錯誤
　・計畫：會弄壞現有流程、遺失規則、害到其他工作階段〕；
(B) 不擋的改善建議。

逐點的做法：
1. 〔你的第 1 點〕：〔我怎麼改、怎麼驗證、結果〕
2. …
沒照你說的做的：〔哪一點、為什麼、我改成怎樣、有什麼事實支持〕
實測：〔逐項〕
```

## 4. 劇本

```
你是這個系列的審稿副手。請用繁體中文獨立審後面附的第〔N〕集劇本，不要只是確認。劇情品質優先，該重寫就說要重寫。

附件：本集劇本、前幾集照剪接順序的台詞字卡、系列設定與製作規則、使用者歷次退稿與叫修的意見。

請回答：
1. 跨集邏輯：人數、年級、時間、誰是誰、規則從哪來、前面埋的伏筆有沒有兌現。逐條列出對不上的地方。
2. 第一次看、沒看過前面的觀眾，哪裡會看不懂？
3. 每一場標一下：笑點／記憶點／爽點，哪幾場三個都沒有？
4. 這個系列的三個問題有沒有回答：〔系列自己的檢核題〕。
5. 最該改的三件事，各附具體改法。

〔1,200〕字以內。
```

## 5. 成片（附每秒一格總表）

```
你是審片副手。請用繁體中文獨立審這支成片，不要只是確認前幾輪。劇情品質優先：有問題就說該重寫或重拍哪一段，不要因為已經拍好就放過。
附件是本集與前幾集照剪接順序的台詞字卡、本集劇本；圖是每秒一格總表（每格左上角有秒數與鏡號）和前幾集的參考畫面。

請回答：
1. 劇情：跨集邏輯（人數、年級、時間、誰是誰、規則從哪來、伏筆有沒有兌現）、第一次看的觀眾懂不懂、轉折有沒有一句話或一個畫面講白。
2. 每一場標一下笑點／記憶點／爽點，哪幾場三個都沒有？
3. 畫面連戲：同一個人前後鏡的服裝、道具、座位、左右手；背景突然多出的人；牆上不該有的旗子或標語。請寫時間碼。
4. 字幕與字卡：有沒有壓到臉、跟台詞對不對。
5. 最該修的五處，照嚴重程度排，各附時間碼與改法（重剪、重拍、還是改劇本）。

使用者對這個系列歷次的意見附在後面，請特別檢查同類問題有沒有再犯。〔1,000〕字以內。
```

## 6. 公開推送前

```
公開 repo 推送前審核。請用繁體中文、〔500〕字以內：
1. 下面這批要推到「公開」GitHub repo 的變更，有沒有不該公開的內容（個資、本機路徑、金鑰、片名與鏡號等片務資料、任何人的原話、別人的權利）或程式錯誤？
2. 可不可以推送？不行就列出要先改的。

背景：〔公開 repo 怎麼產生、跟遠端的同步狀態、有沒有公開端獨有的修改〕。
這次的變更：〔逐檔一行：改了什麼、為什麼〕。
掃描：〔掃了哪些樣式、命中幾個〕。實測：〔逐項〕。
沒有公開的：〔哪些檔刻意不放、原因〕。
```

附件給：已追蹤檔的完整 `git diff`（先存成檔）、每個新增檔的全文。
