# 檢查清單

每一關都要能回答「憑什麼說通過」。**技術通過 ≠ 使用者認可**，兩者分開記錄。

## 1. 需求確認後

- [ ] 人物識別特徵、場景、走向、風格、禁則都寫進需求確認表
- [ ] 需要後製的文字（菜單、簡訊、告示）已標記，**不交给模型生成**
- [ ] 台詞與停頓位置已定，能換算成秒數
- [ ] 未經確認的推測都標成「假設」

## 2. 鏡位契約

- [ ] 每鏡都有 `camera`、`frames`、`lens_mm`、`location`、`target`、`motion`、`visible`
- [ ] 幀數符合 **17n+5**
- [ ] 已列出 `identical_camera_setups` 與 `distinct_setups` 數量
- [ ] 運鏡狀態（static / push）與提示詞一致
- [ ] 已確認哪些鏡**只有一人**、哪些**兩人必須同框**

## 3. 布置圖（生成前）

- [ ] 每鏡都算了一張，人工確認座位、朝向、背景、景別、道具
- [ ] 空景鏡角色已隱藏、道具保留
- [ ] 沒有不該出現的物件（多餘窗、雜物、重複人物）
- [ ] 同機位的鏡頭確認是刻意的，不是誤用

**布置圖通過 ≠ 對嘴或表演通過。**

## 4. 運鏡

- [ ] 運鏡是 `.blend` 內的 keyframe，不是算圖腳本逐格位移
- [ ] 只有真的要運鏡的鏡頭才有 keyframe
- [ ] 重算驗證與原腳本等價（逐格比對）

## 5. 生成前環境

- [ ] Comfy 服務在線、queue 沒有別人的工作、顯存沒被 TTS／LLM 佔用
- [ ] 確認實際 ComfyUI 版本與模型（**目錄名稱不代表實際版本**）
- [ ] 收件鎖正確的 Save 節點 ID
- [ ] 每次修正**另存新版本**，不覆寫已提交的

## 6. 選鏡與返工

逐鏡播放完整動態，檢查：

- [ ] 提前開口／台詞前先動嘴
- [ ] 靜默時仍張嘴
- [ ] 角色增生、重複人物
- [ ] 左右換位、座位漂移
- [ ] 帽／眼等道具異常
- [ ] 手部、道具、背景漂移
- [ ] 全臉與肩頸是否有整體表演（不是只有嘴動）

發現問題**先標原因**，只修必要鏡頭。**禁用嘴／眼 XY 平移貼片修法。**

## 7. 對嘴界線

- [ ] 配音與畫面使用同一份音訊
- [ ] 長靜默段有閉口引導，且未把身體鎖死
- [ ] 未做逐音素量測就照實註明，不寫成「完美對嘴」

## 8. 後製

- [ ] 保比例放大（不拉伸畫面比例）
- [ ] 字幕**不在低解析度先燒再放大**
- [ ] 原音軌封包保持一致
- [ ] 全片解碼、幀數、fps、近黑幀、削波、字幕時序檢查

## 9. 交付與歸檔

- [ ] 成片、字幕、播放入口、採用清單、驗證 JSON、README 齊備
- [ ] 保存使用者回饋原文，不擅自升級為「驗收通過」
- [ ] 記錄耗時**分類**（準備／排隊／生成／QA／返工），不要只記總時間
- [ ] 已寫回專案紀錄（`資源索引/AI短片/`＋入口檔）

## 最常見的失誤（回看用）

| 失誤 | 對策 |
|:---|:---|
| 先批次生成才發現共通缺陷 | 需求訪談＋最難鏡先測 |
| 參考影片用途沒定義 | 在 `subject_definitions` 寫清楚每個 `<Picture N>`／`<Video N>`／`<Audio N>` |
| 標 locked 卻寫運鏡 | 契約與提示詞同步 |
| 誤以為鏡數等於機位數 | 做機位去重 |
| 收錯輸出（把輸入素材當成品） | 鎖 Save 節點 ID |
| 把技術檢查當美感驗收 | 分開記錄 |
| 舊待辦蓋過新結果 | 以最新使用者決策＋採用清單為準 |
