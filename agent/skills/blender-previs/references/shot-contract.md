# 鏡位契約（shot contract）

目的：讓「分鏡」「Blender 相機」「實際生成的畫面」三者對得上，並且**可被程式與下一個對話讀懂**。

## 為什麼需要

本專案已記錄的踩坑：
- 分鏡改成雙人鏡，但 Blender 相機仍是單人構圖 → 生成結果與分鏡不符。
- 標了 locked，提示詞卻寫慢推 → 自相矛盾。
- 13 個鏡號看起來很多，實際上**只有 8 種不同機位**（A1＝C3＝E2＝F1、A2＝C2、A3＝D2）。

## 契約欄位

每鏡至少要有：

| 欄位 | 說明 |
|:---|:---|
| `shot` | 鏡號（A1、B2…） |
| `camera` | Blender 相機物件名（例 `V5_A1`） |
| `frames` | 該鏡幀數（**必須符合影片模型對齊規則**，見下） |
| `lens_mm` | 焦段 |
| `location` / `target` | 相機位置與注視點 |
| `motion` | `static` 或 `push`（附距離與幀數、插值） |
| `delivered` | 交付實際採用的是靜止還是推進（**必須與 motion 一致**） |
| `visible` | 畫面中應該出現誰、誰必須在畫面外 |
| `note` | 特殊限制（不舉紙、無窗背景、閉口引導…） |

機位重複時另存一個 `identical_camera_setups` 區塊，明確列出，並寫 `distinct_setups` 數量。

## 幀數對齊（H3）

H3 的幀數必須符合 **17n+5**：

```
length = max(5, round(sec * fps)) + ((5 - (raw % 17)) % 17)
```

先用配音長度決定秒數，再換算成合法幀數；**不要直接抄別的專案的鏡長**。

## 運鏡的兩種狀態（不可混用）

| 狀態 | 條件 | 提示詞必須寫 |
|:---|:---|:---|
| **locked（靜止）** | 相機在 Blender 內沒有任何 keyframe | 明確寫「完全鎖定三腳架、同焦段同構圖、不得推移搖」 |
| **push / 運鏡** | 相機運動**必須做成 keyframe 存在 `.blend` 內** | 說明相機運動；參考影片提供運鏡 |

**已發生的教訓**：v5 全片只有 F1 真的用了推進，A1／D1 交付版是靜止；若沒有契約表，很容易誤以為 13 鏡都有運鏡。

## 輸出

- `camera_plan_v<N>.json`（機器可讀，給腳本與下一個對話）
- 人類可讀的鏡表（可放在該片 README 或製作計畫）

**契約未定案前，不要開始生成影片。**
