## 1. 劇本

- 用編劇技能。先給 2–3 個敘事方向讓人選，選定後寫完整劇本＋鏡表。
- 劇本就要考慮技術限制：避開快打、追逐；同一鏡只讓一個人說話；畫面上要出現的字先想好由誰做（Image 2.5 畫或後製疊）。
- 喜劇結構「神話層 × 真相層」：先拍得像史詩，切一鏡揭穿其實很日常。

### 1.5 生成前試映（劇本定稿前的最後一關）

在花時間做首幀與 H3 之前，先讓人「看」一遍（做法見 `agent/skills/shanshiba-drama/references/table-read.md`）：

1. 鏡表寫成 `preview/shots.json`（每鏡：鏡號、秒數、一句英文畫面描述、台詞文字 `text` 與字幕 `caption`）。
2. `python tools/make_storyboard.py preview/shots.json`：每 16 鏡一張 4×4 鉛筆草圖（只看故事順序與構圖；要 `OPENAI_API_KEY`，沒有就跳過，試映影片改成只有字幕）。
3. **2026-10-23 起讀本只給文字、不做 TTS**（台詞之後由 H3 拿角色參考音自己念，讀本聲音用不到成片）。`python tools/assemble_read.py preview/shots.json`：照鏡表排時間軸 → 草圖＋字幕的靜音 `讀本試映.mp4`、估計總長、最長三鏡，以及每鏡建議 H3 鏡長 `h3_sec`＝max(3 秒, 台詞字數 ÷ 3＋2 秒)（H3 有時晚 1.5–2.1 秒開口；原頻道 7 句實測全部在這長度內念完，多的剪接時裁掉）。
4. 超長就刪台詞或併鏡，不要加速；看完說「通過」才進首幀。
5. 之後的聲音：每個角色錄一份參考音（要吼的戲另錄兇的）→ H3 自己念 → 聽寫比對 → 念錯換 seed 抽 2 次 → 還錯就請人錄那一句當固定音軌、只重跑那一鏡。要先「聽」讀本才做 TTS 讀本（table-read.md 第 5 節）。原頻道〈颱風假作業包〉實測：讀本 99.7 秒 → 刪兩鏡、縮短無台詞鏡 → 88.6 秒。

## 2. Blender 預演（難的片才做）

- `make_plan.py` 寫鏡位契約（相機位置、目標、焦距、誰在哪）→ `render_layouts.py` 用無介面 Blender 算方塊人布置圖。
- 一張約 0.1 秒，13 張 1 秒左右。順便發現「其實只有 8 個機位」這種重複。
- 布置圖**左右鏡射**後，和角色定妝照一起當 Image 2.5 的參考圖，Image 2.5 照它的機位與站位構圖（提示詞寫明「只照抄機位，不要方塊外觀」）。

## 3. 首幀

> **這份 repo 預設全本地**：角色與首幀改用 Qwen-Image 2.1／Qwen-Image-Edit，做法見 [07_本地角色與首幀.md](07_本地角色與首幀.md)，完整範例是 `pipeline/demo_local/run_demo.py`。下面是原專案用雲端 Image 2.5 時的寫法，構圖、光線、參考圖的原則一樣適用。


`gen_frames.py` 的 SHOTS 表每一列：`(參考圖代號, 光線, 畫面描述, 選項)`。

- 先生「場景母版」（例如阿禾的房間），之後每鏡都拿母版當參考，房間才會一致。
- 每鏡參考圖＝角色定妝照＋場景母版＋布置圖（有的話）。
- 提示詞模板固定：保持角色外觀句、電影感句（變形鏡頭、35mm 顆粒、淺景深、青橘調、**不要黑邊**）、不准有字句、制服句。
- `n=1`、`quality=medium`；參考圖自動縮成一半面積省錢。
- **人工審首幀**後建立空檔 `frames_ok`，後面的 H3 才會開跑。
- **草稿模式（選用）**：`tools/gen_image.py --turbo`（Qwen-Image 2.1 Turbo，固定 8 步、官方 sigma；`setup/downloads_qwen_turbo.json`）一張 2K 約 12 秒（原版 50 步約 63 秒），拿來一次抽很多構圖挑。皮膚偏光滑、特定表情會偏向微笑、暗部偏黑 → **定稿仍用原版 50 步**。`qwen21_face_refine.py --turbo` 同理（實驗性）。
- 動作鏡的首幀畫「動作開始前」的姿勢（見下方 6.「動作寫法」）。

## 4–5. 配音與挑音

```
（2026-10-07 起：台詞表 → jobs.json → make_breezyvoice.cmd，念不準的字標注音；下面是〈D-7〉範例當時的舊流程，留作參考）
voice_plan.py   台詞表 LINES＋TTS 用字替換（念不準的字換同音字，字幕不變）
      ↓
voice_stage1.py ① 參考音逐字稿（ASR）② 產生 Breeze 任務 ③ edge-tts 台灣國語「答案卷」④ VoxCPM2 每句 6 候選（繁轉簡送入）
      ↓
breeze_batch.py Breeze 每句 6 候選
      ↓
voice_pick.py   去頭尾靜音 → 太慢的淘汰 → ASR 必須全對 → 每字音高曲線跟答案卷比
                → 一聲不夠高、升降方向相反額外扣分 → 取最低分
```

- 候選越多越好，一批常常只有 1 個全過。
- 背景很吵的鏡頭，先把環境音疊上去再跑 ASR（`voice_robust.py`），挑在噪音下仍聽得清楚的。
- 換了配音，有台詞的 H3 鏡頭要重拍（嘴型跟著音軌走）。
- **口播／旁白稿**（解說片、開場旁白）：`tools/make_narration.py lines.json out --ref 參考音.wav --ref-text "逐字稿"`。BreezyVoice 一次念 2–3 句（同一段內併塊），塊與塊之間的停頓照結尾標點；自動聽寫挑候選、切掉句尾多念的小字，輸出 `narration.wav`＋`timeline.json`（每句起訖秒數，給字幕用）。不合格的塊 `--reroll K04,K11` 重抽。比一句一句接、固定停頓順很多。

## 6. H3 生成

> **雲端替代（選用）：Seedance 2.5（Kie.ai）**。使用者明說才用。`tools/sd25_shot.py` 吃跟 H3 **同一份分鏡 spec**，可以拿來和 H3 版比較：
> ```
> python tools/sd25_shot.py check  h3/*/spec.json                 # 每鏡模式、秒數、總點數（不送件、不用金鑰）
> python tools/sd25_shot.py submit h3/*/spec.json --out sd25      # 送件（KIE_API_KEY；先查點數，不夠就不送）
> python tools/sd25_shot.py poll   --out sd25                     # 做好下載成 sd25/<鏡>.mp4
> ```
> - **有台詞的鏡一定給角色參考音**：spec 有 `audio.voice_ref` → 參考模式（首幀當參考圖＋參考音，只學音色）；有台詞沒參考音會被擋下，只有角色真的沒有參考音才在 spec 寫 `"self_voice": true`。沒台詞的鏡走首幀模式（構圖釘在首幀）。
> - 720p、每鏡 ≥4 秒、約 63 點／秒。原頻道〈颱風假作業包〉26 鏡比較：2.5 動作與表情較生動（真的跳起來、仰頭），但跳躍時臉會糊、偶爾整個換構圖；H3 臉與服裝最穩、動作偏小（下面「動作寫法」可以補回大半）。
> - **換聲（選用）**：2.5 自己重念的台詞，可用 `tools/cosy_vc.py` 換成角色參考音的音色，每個字的時間不變、嘴型照對（BreezyVoice venv；先用 BS-RoFormer 分離出人聲再換、再混回）。作者實測 14 句：像角色參考音 0.16 → 0.69。念錯的聲調會跟著保留，那句改用 TTS 重配。
> - **換字（選用，2026-11-07）**：只錯一兩個字時不用整句重配，`tools/vc_swap.py job.json`：MMS 強制對齊找到那個字 → Ming 用角色參考音念含那個字的小句 → 切下那個字、照前後字音高移調、拉成原長度接回 → 整句 cosy_vc 換聲抹平接縫。整句長度不變、嘴型照對；同音字技巧可用（`tts`／`tts_at`／`tts_char`）。適合聲調錯、破音字；嘴型差很多的字要看畫面。格式見檔頭，接縫一定要人聽。

### 動作寫法（2026-10-23 起預設，H3 動作偏小的主要解法）

H3 照字面演：spec 的 `action` 只寫一句「全班跳起來歡呼」，它就只會舉手晃一晃。照 MiniMax 官方提示詞技能 `h3-prompt-writing` 的結構寫，動作才會出來：

- **`action` 寫 50–120 個英文字**：「Starting from <Picture 1>, …」**首幀定錨 → 動作開始 → 持續發展 → 結果**；寫出哪個身體部位動、動多大（"until the arms are fully straight"）、做幾次（"again and again"、"about three swipes per second"）；不寫 lively、exaggerated 這類抽象詞（模型不知道要誇張到哪）。
  - 例：「全班跳起來」→ "…bend their knees deeply and spring straight up so their feet leave the floor, then land and jump a second time, pumping both fists above their heads with each jump…"
  - 鏡內時間點（"at about 1.2 seconds …"）選用：官方沒有這條，作者實測只多一點點，要對節拍時再寫。
  - 大動作鏡、背景容易冒人的鏡，action 前先加 2–4 句首幀描述（構圖、人物外觀與位置、光線）：動作量不變，但畫面較釘在首幀（作者 2026-10-24 補測：跳躍頭不出框、背景不冒人）；一般鏡不必寫到官方建議的 350–500 字。
- 作者實測（6 個動作鏡 × 2 seed，光流量動作）：一句話版 0.41 → 官方結構 1.10（**×2.7**）→ 再加時間點 1.19；狂刷手機從完全靜止變成拉近手機＋踢腳、偷偷握拳變成左右張望＋拳頭拉到腰。`tools/h3_shot.py` 對少於 50 字的 `action` 出警告。
- **動作鏡首幀畫「動作開始前」的姿勢**：首幀已經舉手、握拳（動作最高點），H3 只剩維持可演。彈跳等全身大動作首幀要留頭頂空間（跳太高頭會出框、中段糊）。
- **尾幀＝首幀會把人鎖回原姿勢**（實測三種寫法都 100% 靜止）：只用在人不需要動、只要鎖道具／螢幕字的鏡；人要動時尾幀另做「動作完成後的姿勢」，或不鎖、多抽 seed。`h3_shot.py` 偵測到尾幀＝首幀會提醒。
- 動作變大時台詞較容易漏字、晚開口 → 有台詞的動作鏡逐鏡聽寫、抽 2 seed。
- 讓 agent 照官方規則寫：裝官方技能（只是寫作規則，沒有程式）：`npx skills add https://github.com/MiniMax-AI/MiniMax-H3 --skill h3-prompt-writing`，或把官方 repo 的 `skills/h3-prompt-writing/` 複製到你的 `.claude/skills/`。組提示詞仍交給 `h3_shot.py`（它照官方 Ref2VA 六段格式），技能只用來寫 `action`。

### 舞蹈、武打：白模動作參考（2026-10-14 起）

照原片動作做的鏡頭（舞步、武打）不用骨架控制，改成「原片 → 灰色 3D 白模影片 → 當 H3 的動作參考」，手臂形狀、踢腳、落地時間都比骨架準：

```
C:\AI\H3\venv\Scripts\python.exe tools\make_whitemodel.py 原片.mp4 --out 白模.mp4 --start 13.72 --frames 124 --crop 1600:880:220:155 --size 1280x704
```

- 需要 ComfyUI ≥ 0.37（SAM 3D Body、MoGe、SAM 3.1 都是內建節點）＋`setup/downloads_whitemodel.json` 的 4 個模型（約 7.2 GB）。124 格單人約 25 秒、雙人約 55 秒。
- `--crop`／`--size` 先把原片裁到跟首幀人物同位置、同大小；`--frames` 用 17n+5。
- **兩人以上加 `--people 2 --colors red,blue`**（每人固定顏色，身份較不會對調；需要把 `setup/comfy_nodes/whitemodel_color` 複製到 `ComfyUI/custom_nodes/`，重啟 ComfyUI）。工具會印出第 0 格哪個顏色在左／右。
- spec 寫 `"camera_video": {"file": "白模.mp4", "kind": "motion"}`（多人加 `"people": 2`、`"colors": ["red", "blue"]`，依 subjects 順序），`h3_shot.py` 會自動寫成「<Video 1> 只是動作參考」。
- 白模沒有道具（刀、球），道具寫進 `action`；原片只取動作，成片不能出現原片畫面，原片要是你有權使用的素材。
- 其他 spec 選項：`"control"` 可給清單疊多組控制（預設 Fun ControlNet Union 2.0，合計強度 ≤1）；`"first_clip"`＝上一段最後 5／22／39 格當開頭接續長動作；`"raw_prompt"` 跳過六段格式（給只認單一 caption 的 LoRA）。

`plan_h3.py` 的 SHOTS：每鏡角色、動作（英文）、台詞與開口秒數、長度、首幀、尾幀、限制句、環境音。

`pipeline_gen.py` 做的事：
1. 讀 `voice_state.json` 算每鏡時間軸（台詞起點＋長度，至少留 0.6 秒尾巴）。
2. 產生固定音軌 `specs/<id>_guide.wav`：台詞放在指定秒數，其他全是靜音。**不說話的鏡頭也給靜音**，角色才不會亂開口。
   例外：沒有人的鏡頭（螢光筆、印表機）設 `native=True`，讓 H3 自己出音效。
3. 寫 `specs/<id>.json` 交給 `h3_shot.py`：組官方六段提示詞 → 格式檢查 → 送 ComfyUI。
4. 即時品檢：自己切鏡、黑畫面、首尾漂移；不合格換 seed，最多 3 次。

**現行預設：spec 加 `"draft": true` ＝ DMAD 4 步。** 〈D-7〉當時還是 14 步，之後的片都改 DMAD。以下鏡頭仍用 14 步：骨架控制的舞蹈、群舞、細膩的含淚表情、Combat LoRA 拉滿的打鬥。

`run_queue.sh`：每 60 秒看 GPU，使用率 <20% 且 ComfyUI 佇列空連續 3 次才開工，先叫 ComfyUI 釋放顯存，確認顯存真的空了再跑。依序：配音 → Breeze → 挑音 → 等 `frames_ok` → H3。

## 7. 放大

- **放大前：遠景小臉精修（選用，2026-10-24 加入）**。遠景／舞台／教室前方的重要角色，成片（768×1344）臉平均高 < 50 px 時，用 `tools/face_refine.py`：逐格追臉 → 裁大 → H3 低強度重畫（照角色定妝照認人、原片音軌鎖住對嘴）→ 只把臉羽化貼回，每鏡約 30 秒（RTX 5090）。原頻道 3 鏡實測：臉 25–30 px 從一團糊變成認得出本人，還修掉 H3 畫錯的眼鏡；70 px 幾乎沒差（工具自動跳過 ≥ 50 px）；不閃；嘴大致跟原音（有台詞仍要人看）。
  ```
  C:\AI\H3\venv\Scripts\python.exe C:\AI\tools\face_refine.py <鏡資料夾> --ref <角色定妝照> --track          # 6–9 秒：臉多大、選到誰（preview.png）
  C:\AI\H3\venv\Scripts\python.exe C:\AI\tools\face_refine.py <鏡資料夾> --ref <角色定妝照> [--select top_most]
  ```
  吃 `h3_shot.py` 的輸出資料夾（`clip.mp4`＋`shot.json`，提示詞自動組），輸出 `<鏡資料夾>/facerefine/refined.mp4`。**先 `--track` 看選到的是不是主角**：前景有更大的路人臉時改 `--select top_most`／`left_most`…；一次修一張臉。順序：H3 → face_refine → VSR。安裝與限制（只在 ComfyUI 0.40 實測）見 `docs/06_安裝.md`。
- `assemble.py --vsr`：16:9 的 H3 片段先用 RTX VSR ULTRA 放到 1080p（每鏡約 10 秒），快取在 `post/vsr/`。重拍後自動作廢舊快取。
- 全景、舞蹈改用 FlashVSR（要逐鏡看有沒有多畫細節）。
- 不用 SeedVR2、SoL-Refiner：會改臉、改嘴型。

## 8. 後製素材（`post_fx.py`）

全部用 PIL＋numpy 逐格畫，不用剪輯軟體：
- 撕日曆字卡（倒數 D-7、D-1、D-0）
- 咒印名片：法陣慢轉＋標楷體逐字由光浮現＋爆光（`templates/seals/`）
- 手機聊天畫面、角落時間字、三分割欄位的灰／亮調色

## 9. 配樂（`music_scenes.py`）

1. 依 `post/starts.json` 算每段需要幾秒。
2. 每段 MiniMax Music 3 生 3 個 seed；歌詞欄只放 `[Instrumental]` 標籤（約 14 個，太少會太短）。
3. BS-RoFormer 分離，選人聲殘留最低的那個（避免像人聲的長音蓋過台詞）。
4. 不夠長就交叉淡化循環，段與段 2 秒交叉淡化，逐秒調音量。

## 10. 組裝（`assemble.py`）

SEGS 表決定整支片的順序，每段一種類型：`h3`（片段＋裁切）、`split`（三分割）、`cal`（字卡）、`card`（全畫面名片）、`phone`、`end`（片尾）。

- **`trim`／`ss` 裁掉 H3 開口前的空白**（H3 常晚 1.4–2.8 秒才開口）。
- **修剪點一律對齊 1/24 秒**（2026-10-23 修正，範本 `make_film.py` 已改）：每段用 `-frames:v` 取整數格，修剪點沒對齊的話每鏡多出零點幾格，25 鏡累積約 0.3 秒，中段以後嘴型明顯晚於聲音。自己寫組裝腳本時，把每鏡的起訖秒數先四捨五入到格，再用同一個格數排聲音。
- 配音比畫面提前 0.2 秒（`SAY_LEAD`）對嘴最自然。
- 音訊：環境音底（可直接借 H3 原生環境音延長）＋音效庫（`sfx/`）＋配樂；台詞時背景壓到 30%。
- 響度兩段式：loudnorm → 量測後補到 −15.5 LUFS → 限幅。確切指令（`example_D-7/assemble.py` 第 359–363 行）：
  ```
  ffmpeg -i mix.wav -af loudnorm=I=-15.5:TP=-1.5:LRA=11 -ar 48000 ln.wav
  ffmpeg -i ln.wav -af ebur128 -f null -          ← 讀最後的 I: 數值，gain = -15.5 - I
  ffmpeg -i ln.wav -af "volume=<gain>dB,alimiter=limit=0.72:level=false" -ar 48000 final.wav
  ```
  **`alimiter` 一定要加 `level=false`**：預設 `level=true` 會把輸出自動拉到 0 dBFS（2026-10-07 全新安裝測試踩到：成片峰值 0.0 dBFS、−14.6 LUFS）。目標：約 −15.5 LUFS、峰值 −2 dBFS 以下。
- 字幕依說話者上色、句號拆段、前後不重疊。
- 同時輸出手機版 720p（給人在手機上驗收）。
