# 05 AI agent 協作與知識庫

這個專案的腳本幾乎都是 AI agent（Claude Code）寫、也由它執行。真正讓品質穩定的，是**讓下一個 agent 知道上一個學到什麼**。

## 入口檔：CLAUDE.md

- 放在專案根目錄，agent 每次開工自動讀。
- **最新決策寫在最上面**，每條一段：日期、做了什麼、結論、連到詳細文件。舊的不刪，被取代就標「已被取代」。
- 固定段落：專案目標、影片規格、核心決策與否決理由、技術限制、工作注意事項（必讀文件清單）。
- 範本：[agent/CLAUDE.md範本.md](../agent/CLAUDE.md範本.md)。其他 agent 用 `AGENTS.md`（Codex、opencode）、`GEMINI.md`，內容指向同一份知識。

## 知識庫分層

| 層 | 放什麼 | 例子 |
|---|---|---|
| 入口 | CLAUDE.md、專案現況 | 「現在做到哪、下一步」 |
| 總導航 | `資源索引/README.md` | 一行一個主題 |
| **答案索引** | 使用者已接受的做法：參數、踩坑、重現指令 | 「Image 2.5＋H3 製作與踩坑」「H3 快速模式與定稿驗證」 |
| 實測 | 本機 A/B 結果、數字、並排影片 | 「DMAD 4 步 vs 14 步 8 類鏡頭」 |
| 研究 | 網路來源、社群做法（標明「已查閱未實測」） | 「16GB 跑 H3 社群報告」 |
| 每片紀錄 | 劇本、製作紀錄、PROGRESS | 每支片資料夾裡 |

原則：
- 同一件事只有一個詳細來源，其他地方只放連結。
- 「查閱過」≠「裝了」≠「實測過」≠「使用者驗收過」，四種狀態分開寫。
- 網路來源記原始網址、發布日、查閱日、驗證狀態。

## 記憶（一事一檔）

Claude Code 的記憶資料夾，每個檔案一件事，分四類：

| 類型 | 內容 | 例子 |
|---|---|---|
| feedback | 使用者給的規則與退件理由（附「為什麼」與「怎麼套用」） | 「老師不碰學生」「主角腰上以上」「交片前自己跑常退件清單」 |
| project | 專案事實與決定 | 「DMAD 4 步已定為定稿」「H3 單鏡 ≤12 秒」 |
| reference | 外部資源位置 | 「角色聲音參考檔在哪」 |
| user | 使用者是誰、偏好 | — |

`MEMORY.md` 是索引，一行一條。**退件一次就寫一條 feedback**，這是品質累積最快的方式。

## 技能（Skills）

- `agent/skills/shanshiba-drama/`：編劇九階段流程、16:9 劇本格式、審稿清單。
- `agent/skills/blender-previs/`：需求訪談 → 鏡位契約 → 布置圖檢查 → 提示詞包。

> ⚠️ 兩個技能寫於專案早期，裡面還有「Seedance 2.5、30 秒一段」「Qwen 生圖、768p」等舊說法。現行做法以 docs/ 為準（本機 H3、單鏡 ≤12 秒、Image 2.5 首幀、DMAD）。

## 工作習慣（寫進 CLAUDE.md 讓 agent 遵守）

- 開工前先讀現況和相關答案索引；收工前寫回決策、成果路徑、驗證結果、限制、下一步。
- 多步驟工作開跑前**先報每一步的時間與費用**。
- 啟動背景工作後**自己確認真的在跑**（log、佇列、GPU 使用率）。
- 「我去睡了」＝授權自動做完並自審，GPU 不要閒著；早上交成片＋自審報告。
- 一幕一幕做，做完先給人看；認可過的鏡頭不重拍。
- 使用者說「不要用 A 方法避開」時，不要擅自換別的繞路。
- 金鑰不印出、不寫進專案。

## 雙機協作（選用）

原專案有兩台電腦（5090 桌機、4080 筆電）共用雲端硬碟資料夾，各跑各的 agent：
- 交接檔各機一份、只改自己那份；CLAUDE.md 和 git 只在主機改。
- 筆電做不吃顯存的工作：劇本、研究、剪接、ASR、QA、小型 LoRA 訓練。
- 成品放 `交付_<機器>/<任務>/`，最後寫 `done.txt`（檔名、大小、SHA-256），對方看到 done.txt 且雜湊相符才使用。
